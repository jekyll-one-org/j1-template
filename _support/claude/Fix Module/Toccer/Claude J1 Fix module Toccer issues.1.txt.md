Toccer is a table of contents (TOC) generator module for J1 Template, based
on Tocbot (https://tscanlin.github.io/tocbot).

Tocbot supports a scrollSmooth function, but is disabled by default. Instead
of Tocbot's scrollSmooth, a similar function (j1.scrollToAnchor()) is used
from the Template system to scroll the page to the header element (anchor)
selected from the TOC menu generated by Tocbot.

Unfortunately, calling the Template function "scrollToAnchor" negatively
impacts the dynamically generated TOC. The function scrollToAnchor
scrolls inside the related page to the correct y-position (offset) of the
headline selected (what the built-in scrollSmooth function of Tocbot doesn't),
but changes the previously calculated TOC element positions for active
headlines in the dynamic TOC generated by Tocbot (always the last headline
of the previous section is selected as active).

Why is it?

## Warum passiert das?

Der Fehler entsteht durch einen **Offset-Mismatch** zwischen J1s Scroller und
Tocbots Positionsschwelle — die Tocbot-Sourcen selbst sind unschuldig, gefixt
werden muss nur die Adapter-Konfiguration in `toccer.js`:

1. **`j1.scrollToAnchor()` landet 93 px "zu früh".**
   Für statische Seiten scrollt es mit `scrollOffsetCorrection = -93`
   (Navbar-Kompensation, `j1.js`).
   Die angeklickte Headline steht am Ende der Animation also 93 px *unterhalb*
   der Viewport-Oberkante — Tocbots eigener scrollSmooth würde sie auf 0 setzen.

2. **Tocbot markiert rein positionsbasiert.**
   `getTopHeader()` in `build-html.js` gilt: eine Headline ist "erreicht",
   wenn `offsetTop <= scrollTop + headingsOffset + 10`. In `toccer.js` war
   `headingsOffset: 1` hartkodiert → Ziellinie bei `scrollTop + 11`.
   Die Ziel-Headline ruht aber bei `scrollTop + 93`, gilt somit als
   "noch nicht erreicht", und Tocbot markiert `headings[i - 1]` — exakt
   die letzte Headline des vorherigen Abschnitts.
   Die Simulation oben bestätigt es: mit Offset 1 → `h1` (falsch),
   mit Offset 93 → `h2` (korrekt).

3. **Ironie am Rande:** `initToccerCore`
   Berechnet bereits einen `scrollOffset` via `j1.getScrollOffset()`
   verwendet ihn aber nirgends. Tocbots Doku verlangt genau diese
   Verdrahtung (bei `scrollSmoothOffset: -50` gehört `headingsOffset: 50`
   gesetzt).

4. **Sekundäreffekt (Flackern):**
   Weil `scrollSmooth: false` ist, ruft Tocbots interner Click-Listener
   nie `disableTocAnimation()` auf — das Highlighting lief während der
   300-ms-J1-Animation live mit und wanderte durch die Abschnitte.


## Die Fixes (alle getaggt `Claude - Fix J1 Toccer headline issue #1`, 20 Tags)

**Fix A — `headingsOffset` verdrahtet**
Neue Variable `anchorScrollOffset = 93` (mit Design-Note, warum das Literal
bewusst synchron zum hartkodierten `-93` in `j1.scrollToAnchor()` gehalten
wird statt `scrollOffset` wiederzuverwenden — beide Werte können zur
Laufzeit differieren).
`headingsOffset: 1` als deprecated Kommentar erhalten, dann `headingsOffset: anchorScrollOffset`. Das repariert nebenbei auch manuelles Scrollen: bisher
galt eine hinter der fixen Navbar verdeckte Headline bereits als aktiv.

**Fix B — Highlighting während des J1-Scrolls eingefroren:**
Im `onClick` wird `tocbot._buildHtml.disableTocAnimation(event)` gerufen
(wie Tocbot es nativ täte), und nach
   `scrollToAnchorDelay + scrollSmoothDuration + 100 ms`
folgt `enableTocAnimation()` plus ein erzwungener `tocbot._scrollListener()
Resync an der Ruheposition — der dank Fix A jetzt auf der angeklickten
Headline landet.
